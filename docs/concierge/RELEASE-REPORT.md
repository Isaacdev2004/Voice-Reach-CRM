## What is working and tested

- Integrated subscriber route /dashboard/concierge and staff route /dashboard/admin/concierge, using the current dashboard shell, Clerk requireUserId owner boundary and gated sidebar entry. Disabled/unenrolled accounts receive no feature navigation and server-side denial.
- Save/resume partial discovery, optimistic version conflict protection and idempotent request IDs with payload binding. Business answers inform recommended template categories and suggested pipeline review. Existing Brand Kit remains authoritative and editable in Settings; discovery does not overwrite it.
- Three new server-only tables: concierge_cases, concierge_events, concierge_imports; two service-role-only SECURITY INVOKER RPCs with fixed search_path. RLS and revoked browser grants. No new auth/billing system, no existing CRM schema changes.
- Reviewed CSV mapping/preview, 1 MB/500 rows/50 unique columns, malformed CSV/field checks, duplicate detection within file and against owned CRM records, explicit privacy and execution confirmations, stable preview IDs, atomic confirmation and consent records, contact cap checks, cancellation before execution, saved preview recovery and error summaries. Existing contacts are never overwritten; duplicates are skipped. All imported contacts are DNC-suppressed with consent Unknown. Tags/category/follow-up dates are preserved in notes for review, not silently interpreted as automation permission. Unmapped columns are not imported. The raw file is not retained. In-flight source rows are retained in the owner-only preview for up to 24-hour eligibility; completed/cancelled imports clear rows. Expired preview rows are cleared on the subscriber's next import-history access; no continuous purge worker is claimed.
- Campaign Concierge previews and saves the existing reviewed premium draft catalog through the existing campaign builder action=template with provider=mock, no contactIds, no enrollment or activation. Subscriber confirmation required. Underlying Starter restrictions are enforced for multi-step Concierge saves. Serial approvals check existing builder script identity and do not overwrite existing campaigns. Overlapping requests use case-version claims. A failed or partly completed save directs the subscriber to inspect the campaign editor before retrying; this is not a transactional rewrite of the existing campaign service.
- Eligible Assistant users can explicitly open existing AI setup/campaign proposals; all Assistant entitlements, tools, metering and approvals remain in the existing Assistant system. No automatic AI calls. Disabled accounts receive deterministic/manual paths. Saved campaign edits use the existing campaign editor.
- Integration status distinguishes configuration from verification. An explicit read-only verification action reuses the existing Settings onboarding verifier for Twilio sender ownership and Google calendar retrieval. Partial optional-schema/provider failures remain errors. Email verification and real Assistant generation stay pending until performed in their existing workflows. No credentials are collected or shown to staff.
- Staff role allowlists: admin/manager can manage eligible cases; specialist can read/edit assigned cases; sales can view only assigned operational status. Sales responses redact business discovery, internal notes, subscription details and communication drafts. No subscriber impersonation or staff contact-list browsing is introduced. Reads use existing audit logging, writes use durable case events. Assignment validates authorized staff IDs. Next follow-up dates and internal operational notes are durable; staff stage is not a fabricated readiness completion.
- Seven contextual walkthroughs, subscriber-attested training completion, truthful eight-milestone readiness score, next-step navigation, saved import/campaign evidence, manual launch review. Nothing launches on reaching 100%.
- Day 0/1/2/3/5/7/10/13 onboarding messages are drafts, filtered by actual case age and incomplete milestones. Subscriber consent is visible; it is not treated as send approval. No scheduler, sender, campaign enrollment or invite is installed.
- Operational metrics derive from authorized cases: workload by stage, no-update-in-seven-days flag, readiness and saved subscription status, discovery/import/campaign-review/training completion, and actual event-based mean time to first draft. History begins with actual new events; no historical data is invented.

## Known limitations and release blockers

- Protected hosted Preview and actual two-account Clerk development sessions require branch-specific credentials/eligible test IDs for feat/myari-concierge. The existing secure values are scoped to feat/ai-operating-assistant; they are not automatically available on this branch. No custom staging environment exists. Do not copy Production credentials or deploy with inherited live services.
- Missing secure Preview overrides: test Supabase URL/public key/service credential, matching Clerk development pair and redirects, empty live Stripe/Twilio/email/voice/OAuth credentials, ALLOW_LIVE_OUTBOUND=false, Assistant/sending/new AI billing flags false, Concierge enabled only for two authorized development test IDs, synthetic staff IDs. OpenAI can remain empty for deterministic acceptance; real AI needs separate nonproduction credentials and existing Assistant eligibility. Never paste credentials in chat/source.
- Full 14-category Concierge campaign coverage is not claimed. Reuses 13 existing premium drafts, including commercial/referral/review content. Additional investor/FSBO/expired-listing/appointment-specific content requires reviewed catalog additions. Existing templates are preserved.
- Human training booking, last human contact verification, staffing notifications and service-level escalation are manual via existing authorized calendar/activity workflows. No live scheduling integration or staff communication is invented.
- Registration-to-onboarding, abandonment, trial-to-paid conversion, first authorized launch and support-resolution analytics are not complete historical funnels. Current case/event evidence is measured without fabricated registration denominators. Additional event instrumentation and cohort reporting require another reviewed change.
- Integration readiness is conservative: credentials alone never mark a step connected. The readiness score requires explicit review/not-applicable decisions while full multi-provider verification is incomplete. Financing Studio operational verification is outside this feature.
- Shared-team CRM access is not introduced. Clerk userId remains workspace owner_id. Questionnaire team selection does not grant seats or Pro features. Sales status access is not a CRM permission grant.
- CSV retention cleanup is on access, not a scheduled deletion guarantee; a bounded retention worker and business-approved retention periods should be reviewed before broad rollout. Case history/operational notes require an approved retention policy and existing data-deletion process integration.
- Preview storage/plan-limit concurrency is serialized for Concierge imports; other existing contact-creation endpoints do not share this advisory lock. This does not claim a global rewrite of legacy import or contact-limit enforcement.
