01 What is MCP and why does it matter here

MCP (Model Context Protocol) is an open standard developed by Anthropic that lets Claude securely connect to external tools, databases, and APIs. Think of it as a controlled API bridge — Claude can call functions you define, and those functions talk to Voice Reach CRM on Claude's behalf.

Once this is set up, Kikzeny can say things like "Add Marcus Johnson as a new buyer lead interested in Winter Park under $450K" or "Pull up all hot leads in Seminole County this week" — and Claude will execute those actions directly in the CRM.

What this unlocks No shared passwords. No manual data entry. Claude reads from and writes to Voice Reach CRM through a secure API layer your developer controls entirely.
Prerequisite Voice Reach CRM must expose a REST API (or have one added). This spec covers both building the MCP server AND the API endpoints the CRM needs to support it.

02 Architecture overview

┌─────────────────────────────────────────────────────────┐ │ KIKZENY'S CONVERSATION │ │ "Add a new lead — Marcus Johnson" │ └────────────────────────┬────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────┐ │ CLAUDE (claude.ai) │ │ Reads available MCP tools, decides which │ │ tool to call, formats the arguments │ └────────────────────────┬────────────────────────────────┘ │ MCP Protocol (JSON-RPC 2.0) ▼ ┌─────────────────────────────────────────────────────────┐ │ MCP SERVER (your new Node.js app) │ │ Hosted on Vercel / Railway / Render │ │ │ │ Tools exposed: │ │ • crm_create_contact • crm_get_leads │ │ • crm_update_stage • crm_log_activity │ │ • crm_search_contacts • crm_get_pipeline │ │ • crm_schedule_followup • crm_get_stats │ └────────────────────────┬────────────────────────────────┘ │ HTTPS REST API calls ▼ ┌─────────────────────────────────────────────────────────┐ │ VOICE REACH CRM (voice-reach-crm.vercel.app) │ │ Your existing Next.js application │ │ + new /api/mcp/* routes to add │ └─────────────────────────────────────────────────────────┘
Two parts to build Part A: Add REST API routes to Voice Reach CRM (if not already there). Part B: Build the MCP server that wraps those routes and exposes them to Claude. This doc covers both.

03 How a tool call works end-to-end

  1. Kikzeny types a request in Claude "Add a new buyer lead — Sarah Kim, sarah@email.com, (407) 555-0198, interested in Oviedo homes under $380K, referred by HVAC client."
  2. Claude identifies the right tool Claude reads the list of available MCP tools and their descriptions, then decides to call crm_create_contact with the parsed arguments.
  3. Claude sends a tool call to the MCP server The MCP server receives a JSON-RPC call with the tool name and structured parameters.
  4. MCP server calls the Voice Reach CRM API The server makes an authenticated POST to /api/contacts on the CRM, passing the lead data.
  5. CRM creates the record, returns confirmation The API returns the new contact ID and record URL.
  6. Claude reports back to Kikzeny "Done! Sarah Kim has been added as a buyer lead in Oviedo under $380K. I tagged her as referred by an HVAC client. Want me to schedule a follow-up task for tomorrow?"

05 Authentication approach

Use a simple API key pattern — no OAuth needed for a single-user setup. The MCP server holds the key; Claude never sees it.

src/auth.ts 
import axios from 'axios';

// Axios instance pre-configured with CRM auth header
export const crmClient = axios.create({
  baseURL: process.env.CRM_BASE_URL,
  headers: {
    'Authorization': `Bearer ${process.env.CRM_API_KEY}`,
    'Content-Type': 'application/json',
    'x-mcp-client': 'claude-mcp-server/1.0'
  },
  timeout: 10000
});

// Middleware to validate MCP server is being called by Claude Desktop
export function validateMCPSecret(secret: string): boolean {
  return secret === process.env.MCP_SERVER_SECRET;
}
CRM side — add this middleware to Voice Reach CRM All /api/mcp/* routes on the CRM should validate the Authorization: Bearer YOUR_KEY header. Reject any request without it with a 401. Generate a strong random key with: openssl rand -hex 32

06 MCP tools to build

These are the 8 tools Claude will be able to call. Each maps to one or more CRM API endpoints. Write descriptions carefully — Claude uses them to decide which tool to call.

crm_update_stage Move a lead to a new pipeline stage (New / Active / Hot / Under Contract / Closed) /api/contacts/:id/stage PUT

07 Full MCP server code

src/index.ts — complete MCP server 
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from '@modelcontextprotocol/sdk/types.js';
import { z } from 'zod';
import { crmClient } from './auth.js';
import 'dotenv/config';

// ─────────────────────────────────────────────────────────
// Initialize MCP Server
// ─────────────────────────────────────────────────────────
const server = new Server(
  { name: 'voice-reach-crm', version: '1.0.0' },
  { capabilities: { tools: {} } }
);

// ─────────────────────────────────────────────────────────
// TOOL DEFINITIONS
// Claude reads these descriptions to decide which tool to call.
// Write them like instructions to a smart assistant.

server.setRequestHandler(ListToolsRequestSchema, async () => ({

// ─────────────────────────────────────────────────────────
// TOOL HANDLERS
// Each tool calls the appropriate CRM API endpoint
// ─────────────────────────────────────────────────────────
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;

  try {
    switch (name) {

      // ── CREATE CONTACT ────────────────────────────────────
      case 'crm_create_contact': {
        const response = await crmClient.post('/contacts', {
          firstName:    args.first_name,
          lastName:     args.last_name,
          email:        args.email,
          phone:        args.phone,
          stage:        args.stage ?? 'New Lead',
          leadSource:   args.lead_source,
          buyerCriteria: {
            priceMin:   args.price_min,
            priceMax:   args.price_max,
            targetAreas: args.target_areas,
            bedroomsMin: args.bedrooms_min,
            preApproved: args.pre_approved
          },
          notes: args.notes,
          tags:  args.tags
        });
        return {
          content: [{
            type: 'text',
            text: `Contact created successfully. ID: ${response.data.id}. Name: ${args.first_name} ${args.last_name}. Stage: ${args.stage ?? 'New Lead'}.`
          }]
        };
      }

      // ── SEARCH CONTACTS ───────────────────────────────────
      case 'crm_search_contacts': {
        const response = await crmClient.get('/contacts/search', {
          params: {
            q:     args.query,
            stage: args.stage,
            tag:   args.tag,
            area:  args.area,
            limit: args.limit ?? 10
          }
        });
        const contacts = response.data.contacts;
        if (contacts.length === 0) {
          return { content: [{ type: 'text', text: 'No contacts found matching those criteria.' }] };
        }
        const summary = contacts.map((c: any) =>
          `• ${c.firstName} ${c.lastName} | ${c.stage} | ${c.phone ?? 'no phone'} | ${c.email ?? 'no email'} | ID: ${c.id}`
        ).join('\n');
        return { content: [{ type: 'text', text: `Found ${contacts.length} contact(s):\n\n${summary}` }] };
      }

      // ── GET SINGLE CONTACT ────────────────────────────────
      case 'crm_get_contact': {
        const response = await crmClient.get(`/contacts/${args.contact_id}`);
        const c = response.data;
        return {
          content: [{
            type: 'text',
            text: JSON.stringify(c, null, 2)
          }]
        };
      }

      // ── UPDATE STAGE ──────────────────────────────────────
      case 'crm_update_stage': {
        await crmClient.put(`/contacts/${args.contact_id}/stage`, {
          stage: args.stage,
          note:  args.note
        });
        return {
          content: [{
            type: 'text',
            text: `Stage updated to "${args.stage}" for contact ${args.contact_id}.${args.note ? ' Note logged: ' + args.note : ''}`
          }]
        };
      }

      // ── LOG ACTIVITY ──────────────────────────────────────
      case 'crm_log_activity': {
        await crmClient.post(`/contacts/${args.contact_id}/activities`, {
          type:    args.activity_type,
          summary: args.summary,
          outcome: args.outcome,
          date:    args.date ?? new Date().toISOString()
        });
        return {
          content: [{
            type: 'text',
            text: `Activity logged: ${args.activity_type} — "${args.summary}"${args.outcome ? '. Outcome: ' + args.outcome : ''}`
          }]
        };
      }

      // ── SCHEDULE FOLLOW-UP ────────────────────────────────
      case 'crm_schedule_followup': {
        const response = await crmClient.post('/tasks', {
          contactId: args.contact_id,
          type:      args.task_type,
          dueDate:   args.due_date,
          note:      args.note,
          priority:  args.priority ?? 'normal'
        });
        return {
          content: [{
            type: 'text',
            text: `Follow-up task created: ${args.task_type} due ${args.due_date}. Task ID: ${response.data.id}`
          }]
        };
      }

      // ── GET PIPELINE ──────────────────────────────────────
      case 'crm_get_pipeline': {
        const response = await crmClient.get('/pipeline', {
          params: { stage: args.stage_filter, area: args.area_filter }
        });
        const p = response.data;
        const summary = Object.entries(p.stages).map(([stage, data]: [string, any]) =>
          `${stage}: ${data.count} leads`
        ).join('\n');
        return {
          content: [{
            type: 'text',
            text: `Pipeline overview:\n\n${summary}\n\nTotal active leads: ${p.totalActive}`
          }]
        };
      }

      // ── GET STATS ─────────────────────────────────────────
      case 'crm_get_stats': {
        const response = await crmClient.get('/stats', {
          params: { period: args.period ?? 'this_week' }
        });
        return {
          content: [{
            type: 'text',
            text: JSON.stringify(response.data, null, 2)
          }]
        };
      }

      default:
        return {
          content: [{ type: 'text', text: `Unknown tool: ${name}` }],
          isError: true
        };
    }

  } catch (error: any) {
    return {
      content: [{
        type: 'text',
        text: `CRM API error: ${error.response?.data?.message ?? error.message}`
      }],
      isError: true
    };
  }
});

// ─────────────────────────────────────────────────────────
// START SERVER
// ─────────────────────────────────────────────────────────
async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  console.error('Voice Reach CRM MCP Server running');
}

main().catch(console.error);

08 CRM API endpoints to add (Voice Reach CRM side)

These routes need to exist on voice-reach-crm.vercel.app. If the CRM already has them, just confirm the request/response shapes match. If not, add them as Next.js API routes.

Example: /api/contacts route (Next.js)

pages/api/contacts/index.ts — Voice Reach CRM repo 
import { NextApiRequest, NextApiResponse } from 'next';
// import your DB client here (Prisma, Supabase, MongoDB, etc.)

// Validate the MCP server API key
function isAuthorized(req: NextApiRequest): boolean {
  const authHeader = req.headers.authorization;
  return authHeader === `Bearer ${process.env.CRM_MCP_API_KEY}`;
}

export default async function handler(req: NextApiRequest, res: NextApiResponse) {

  if (!isAuthorized(req)) {
    return res.status(401).json({ error: 'Unauthorized' });
  }

  // POST /api/contacts — create new contact
  if (req.method === 'POST') {
    const { firstName, lastName, email, phone, stage, leadSource, buyerCriteria, notes, tags } = req.body;

    // TODO: Replace with your actual DB write
    const contact = await db.contact.create({
      data: { firstName, lastName, email, phone, stage, leadSource, buyerCriteria, notes, tags }
    });

    return res.status(201).json({ id: contact.id, success: true });
  }

  // GET /api/contacts — list all
  if (req.method === 'GET') {
    const contacts = await db.contact.findMany({ take: 50 });
    return res.json({ contacts });
  }

  res.status(405).json({ error: 'Method not allowed' });
}

12 Developer launch checklist

Voice Reach CRM (existing app)

  • Add API routes — /api/contacts, /api/contacts/search, /api/contacts/:id, /api/contacts/:id/stage, /api/contacts/:id/activities, /api/tasks, /api/pipeline, /api/stats
  • Add API key auth middleware — validate Authorization: Bearer header on all /api/* routes
  • Generate a strong API key — openssl rand -hex 32 — store in Vercel environment variables
  • Test each endpoint with Postman or curl before connecting MCP
  • Confirm CORS allows requests from localhost:3001 during development

MCP Server (new repo)

  • Clone/create repo and install dependencies per Section 4
  • Copy src/index.ts from Section 7 — update field names to match your actual DB schema
  • Fill in .env with CRM_BASE_URL, CRM_API_KEY, MCP_SERVER_SECRET
  • Run npm run build — confirm no TypeScript errors
  • Add to Claude Desktop config per Section 9 with correct absolute path
  • Restart Claude Desktop — confirm hammer icon appears
  • Run all 7 test prompts from Section 10 — confirm each returns real CRM data
  • Delete the test contact (John Doe) from the CRM after testing
